# SEO map — ДаДом

| URL | Назначение | Индексация | Условие публикации |
| --- | --- | --- | --- |
| `/` | Главная | да | production-конфигурация включена |
| `/projects` | Каталог проектов | да | есть хотя бы один реальный опубликованный проект |
| `/projects/[slug]` | Карточка проекта | да | запись `published` и полный набор проверенных данных |
| `/portfolio` | Реализованные дома | да | есть опубликованные кейсы |
| `/portfolio/[slug]` | Кейс | да | запись `published` |
| `/complectations` | Комплектации | да | согласованное содержимое |
| `/technology` | Технологии | да | есть опубликованный технический материал |
| `/technology/[slug]` | Техническая статья | да | автор, проверка, источники и `published` |
| `/articles` | Блог | да | есть опубликованная статья |
| `/articles/[slug]` | Статья | да | автор, дата, источники и `published` |
| `/about`, `/contacts`, `/privacy` | Служебные страницы | нет до заполнения | подтверждённый контент и контакты |
| `/visual-preview/*` | Внутренняя проверка UI | нет, 404 в production | никогда не включать в sitemap |

## Главная страница

- Единственный видимый H1: «Скажи ДА своему новому дому!». Он сохраняет эмоциональную подачу бренда и не дублируется скрытым текстом.
- Видимое описание деятельности в шапке: «Строительство каркасных домов · Екатеринбург и Урал».
- Коммерческие запросы раскрываются естественно в содержательных разделах каталога, комплектаций и технологий, а не добавляются в hero искусственно.

## Canonical, фильтры и пагинация

- Канонический URL формируется только для чистого маршрута страницы.
- Параметры фильтрации и сортировки не должны становиться самостоятельными посадочными без уникального спроса, текста и ассортимента; до этого они `noindex`.
- Не назначать первой странице canonical для всех страниц пагинации. Когда появится реальная пагинация, каждая доступная страница должна иметь собственный URL, а страницы без товаров — 404 или `noindex`.

## Карта внутренней перелинковки

`Главная → проекты → карточка проекта → комплектация / заявка`

`Главная → технологии → материал → связанные опубликованные проекты`

`Статья → релевантная технология / проект → заявка`

Связи добавляются только для реальных опубликованных сущностей.
