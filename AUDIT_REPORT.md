# Независимый аудит «ДаДом»

Дата: 16 ноября 2026. Проверен фактический код и локальная работа приложения, а не только предыдущие отчёты.

Область: рабочий проект в D:/!Борчанинов/ДаДом. Стек сохранён: Next.js 16.4.6, React 19.3.0, TypeScript strict, Tailwind 4.3.3. Новые зависимости не добавлялись. Дизайн-система, палитра, архитектурный характер и основная композиция сохранены.

**Вывод:** технический фундамент готов к добавлению первых проверенных проектов без переписывания компонентов. **Сайт не готов к коммерческому запуску:** отсутствуют реальные контакты, предложения, портфолио, юридические документы и работающий приём заявок.

Это не нагрузочное тестирование под реальным трафиком. При частом наполнении несколькими редакторами нужен следующий этап CMS, а не усложнение текущего интерфейса.

### Браузер и адаптивность

Проверка через встроенный Chromium-браузер. Реальные public-данные оставались пустыми. Для заполненных вариантов использовался временный локальный dev-only экран тех же компонентов, затем удалённый.

| Экран | 320 | 375 | 390 | 768 | 1024 | 1440 |
|---|---|---|---|---|---|---|
| Главная, финальная production-сборка | OK | OK | OK | OK | OK | OK |
| Заполненный шаблон проекта | OK | OK | OK | OK | OK | OK |
| Проект без изображения/цены/характеристик | OK | OK | OK | OK | OK | OK |
| Карточки и фильтры с тестовыми записями | OK | OK | OK | OK | OK | OK |
| Шаблон портфолио | OK | OK | OK | OK | OK | OK |
| Контекст выбранного проекта | OK | OK | OK | OK | OK | OK |

OK означает отсутствие горизонтального переполнения по DOM-геометрии; дополнительно визуально просмотрены первый экран, мобильная страница проекта, фильтры/карточки и ошибка изображения. Не означает визуальный снимок каждого блока на каждой ширине.

Основные маршруты просмотрены в браузере при мобильной ширине 375 px; уникальные метаданные, H1 и отсутствие горизонтального скролла подтверждены. Проверены открытие меню, Escape и возврат фокуса, переход с главной в каталог. Кнопки расчёта передают slug; заполненное разрешение контекста подтверждено компонентным/route-тестом. Полный production-переход с настоящим опубликованным проектом невозможен до его предоставления.

На тестовом отсутствующем файле получен ожидаемый 404; после прокрутки lazy-изображения показана заглушка «Изображение пока недоступно». В тестовом dev-экране были предупреждения LCP о поздней загрузке изображения. Основной галерее добавлен приоритет первого кадра; карточки ниже фильтров остаются lazy. В финальной свежей production-вкладке главной ошибок/предупреждений консоли не зарегистрировано. Это не утверждение об отсутствии любых ошибок на будущем контенте.

### Производительность: измерено

- Главная: 9 внешних script-файлов, суммарно **596 202 байта** JS после декодирования.
- Их локальный gzip: **185 234 байта**. Это расчёт сжатия, не измерение сетевого трафика браузера/CDN.
- Исходный hero-concept.png: **3 276 079 байт**.
- Оптимизатор Next, Accept: image/webp, q=75: вариант w=640 — **53 852 байта**, w=1080 — **140 956 байт**, оба HTTP 200 image/webp.
- Главная использует приоритетную загрузку hero и зарезервированный размер. Карточки/вторичные изображения lazy; планы contain. Шрифты системные, внешней загрузки шрифтов нет.
- Client Components ограничены интерактивным меню, fallback изображения и error boundary; каталожная бизнес-логика остаётся на сервере.

### Ограничения и невыполненные проверки

- Lighthouse отсутствовал в установленном наборе инструментов. Оценки Mobile/Desktop не приводятся.
- Нет полевых Core Web Vitals и достоверных LCP/INP/CLS. Performance API недоступен в используемом read-only браузерном интерфейсе; выводы о размере ресурсов не подменяют эти метрики.
- Не выполнялись нагрузочный тест, cross-browser Safari/Firefox, физические устройства, полноценный screen-reader/WCAG-аудит.
- Не проверены реальные домен/DNS/TLS/CDN, Search Console, публикация на хостинге, индексирование и реальная отправка заявки — они не настроены.
- Не проводилась актуальная онлайн-проверка уязвимостей зависимостей; успешная offline-установка не означает отсутствие CVE.
- Проверка 100 записей — алгоритмическая, не 100 реальных страниц на production-хостинге.
- Валидация не может подтвердить достоверность цены, права на фото, инженерную корректность планировки или юридический текст. Это ответственность редакционной/профильной приёмки.
- Автотесты не являются полной браузерной E2E-suite: используется node:test, SSR и реальные обработчики, плюс отдельные ручные браузерные проверки.

## E. Что необходимо предоставить владельцу

1. **Контакты и реквизиты:** рабочие телефон/email, мессенджеры, часы связи, адрес при наличии, юридическое наименование и реквизиты.
2. **Первый реальный проект:** название, описание, площадь/габариты/этажи/комнаты/спальни, назначение, подтверждённые визуализации и читаемые планы всех этажей.
3. **Коммерческие условия:** комплектации, включённые и исключённые работы, стоимость именно указанного состава, дата актуальности, ограничения по участку/географии и дополнительные расходы.
4. **Портфолио:** реальные фото готовых домов и строительства, описание работ, характеристики, разрешённая география, согласия на публикацию, связь с проектом при наличии.
5. **Факты о компании:** команда, процессы, контроль качества, технология/узлы/материалы, доказательства заявляемых гарантий и опыт — только документально подтверждённое.
6. **Юридические материалы:** утверждённые политика обработки данных, согласие, сведения об операторе; требования к хранению и передаче заявок.
7. **Приём обращений:** выбранный канал/сервис, ответственный сотрудник, сценарии успешной отправки/ошибки, защита от спама; доступы передаются безопасно, не через публичные файлы.
8. **Запуск и фирменный стиль:** реальный домен/хостинг, утверждённый логотип и favicon, OG-изображение, права на используемые материалы.
9. **Содержательные ответы FAQ:** условия адаптации проекта, расчёта, подготовки участка и последовательности работ. Сейчас ответы общие, не готовый продающий контент.

Без пунктов 1–3 и 6–8 запуск рекламного трафика преждевременен. Отсутствие портфолио нельзя маскировать выдуманными объектами.

## F. План следующих этапов

1. **P0 — редакционная приёмка:** получить контакты/реквизиты, один проект с планами и комплектацией, проверить права. Наполнить по README, прогнать проверки.
2. **P0 — юридическая и конверсионная готовность:** согласовать документы и реальный способ связи. Если нужна форма — отдельный серверный обработчик с валидацией, согласием, антиспамом, rate limiting, логированием без утечки персональных данных и подтверждённым результатом.
3. **P1 — приёмка первого реального предложения:** пройти в staging путь главная → фильтр → проект → планы → цена/состав → обращение; проверить реальные файлы и отсутствие противоречий.
4. **P1 — наполнить доверительные разделы:** компания, технология, реальные объекты, точные FAQ; не добавлять искусственные SEO-страницы.
5. **P1 — предпубликационная проверка:** домен/HTTPS, финальные иконки и OG, canonical/robots/sitemap, Lighthouse desktop/mobile и доступность, зависимости/CVE; только затем включить SITE_INDEXABLE и пересобрать.
6. **P2 — наблюдаемость и продвижение:** с необходимыми согласиями подключить измерение успешных обращений и ошибок, Search Console и мониторинг доступности.
7. **P2 — CMS при реальной потребности:** заменить файловый источник адаптером с теми же типами и правилами публикации. Не создавать сейчас сложную административную панель.

Изменения проверялись по React-чеклисту (server/client границы, повторное использование, доступность, изображения) и сквозному сценарию данных. Эти проверки повлияли на уменьшение клиентской логики и явное разделение выбора проекта и отправки заявки. Они не заменяют измерения и ограничения, перечисленные выше.
